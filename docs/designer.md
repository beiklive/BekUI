## 界面信息架构（按专业评审整改）

评审的核心结论是"功能不少，但主次不清" —— 按它的 P0/P1 顺序改：

| 评审点 | 现在的做法 |
|---|---|
| 工具栏严重拥挤、功能无主次 | 拆成 **菜单栏（文件/编辑/视图/工具/帮助，全局与低频）+ 常用操作栏（打开项目 / 主题 / 设为默认 / 保存 / 撤销 / 重做）**；当前文件名右对齐显示、带未保存圆点，长路径只给悬停 |
| 配色没有语义体系 | 换成 **VS Code Dark+ 语义色**：编辑器 `#1E1E1E` / 侧栏 `#252526` / 面板 `#333333` 三层底色；交互蓝 `#0E639C`（悬停 `#1177BB`）、焦点 `#007FD4`、选中背景 `#094771`；语义色 错误 `#F14C4C` / 警告 `#CCA700` / 通过 `#89D185` / **未保存 `#E2C08D`** |
| 配色不应跟着被编辑的主题走 | 已改为**固定 VS Code 调色板** —— 工具界面必须是稳定参照物，否则"看到的界面"和"被调的界面"会混在一起 |
| 界面尺寸偏大 | 顶栏/菜单里有 `界面 75/85/100/115/130%`，同时作用于字体与全部间距；默认 85% |

> 界面上方**只有菜单栏**：原来菜单栏下面还有一条细状态行（工程 · 模式 · 当前文件 · 未保存 · 只读），
> 实测它是**空条**、没有任何内容，已删除（`drawTopBar` 一并移除）；
> 其中唯一有用的「基准主题只读」挪到了菜单栏右侧，文件与未保存圆点本来就在那里。
| 不同窗口尺寸 | `BKLV_DESIGNER_WINDOW=宽x高` 可指定窗口尺寸（自查手段之一）；已复核 1024×640 与 1600×900 |

### 第 2 轮：左侧资源 / 节点树重组（P1）

评审意见："树里名称、field 属性、操作按钮和缩进挤在狭窄区域，容易变成一张密集配置清单"。

- 树里**只显示层名**，绘制类型用一个 **VS Code 语法色的徽标**标出
  （rect 青 `#4EC9B0` / text 橙 `#CE9178` / image 蓝 `#569CD6` / shadow 绿 `#6A9955` /
  custom 紫 `#C586C0`），后面跟"字段数"
- **字段默认不再铺开**（`只看层` 默认开）—— 详细字段归右侧检查器，
  要在这里看就展开那一层的箭头
- 徽标位置用 `GetTreeNodeToLabelSpacing()` 算文字起点 —— 直接拿 `ItemRectMin()` 当起点
  会把徽标盖在层名上（第一次就是这样）；"字段数"在窄栏里会让开右侧那排 ↑↓✕ 按钮

### 第 3 轮：右侧检查器重组（P1）

评审意见："右侧大量同款标签 + 数值框纵向排列，要靠逐行读文字才能理解参数关系；
默认值 0.0 占视觉面积；盒模型/布局/颜色/层之间缺分组边界。"

- 盒模型拆成可折叠分组：**尺寸 / 内边距·外边距 / 圆角与描边 / 间距与伸缩 / 其它（JSON 手写的）**，
  **相关的值成对并排**（两个一格）；布局、颜色、layers 也统一成同样的分组头
- 每行不再挂一个 ✕（很占横向空间），**移除字段收进右键菜单**
- 顺手修掉一个真问题：检查器原来只认数字，于是 `"auto"` / `"50%"` / `@theme/metric.*`
  这些**长度写法显示成"未设置"、等于看不到也改不了**（`rectangle` 的 `height` 就是 `"auto"`）。
  现在按值类型分派：字符串 → 文本输入（回车确认）、**数组 → 按元素编辑**
  （`margin[0,4,0,4]` 四个格子，core 新增 `setBoxArrayElement()` + 测试）、数字 → 拖拽框

### 第 4 轮：画布空间与交互状态色（P1/P2）

- 画布上方原来有 3~4 行文字（尺寸说明、缩放说明、主题目录、模式说明）抢注意力 →
  合成**一行**：`420×220 · 0.33× · …/theme/my-skin [720p]`，详细解释降级到悬停提示
- **绘制顺序条可折叠**（预览工具栏里的「层序条」开关）：占的是画布横向空间，可以关掉让位
- 硬编码的状态色换成语义取色：错误 → `errorColor()`、警告 → `warningColor()`、
  通过 → `successColor()`（VS Code 语义），不再各处散写 `ImVec4(...)`

## 跑起来

```bash
cmake -S . -B build/gl -DBKLV_GRAPHICS=gl && cmake --build build/gl
./dist/designer
```

启动时用仓库自带的 `default` 主题（**只读**：基准主题不许就地改）先给用户浏览；
要动手改就点「新建项目」：

| 模式 | 行为 |
|---|---|
| 模板新建 | 复制模板主题成新主题 + 在目标仓库的 `themes.json` 里登记；原主题字节不变 |
| 直接编辑 | 写回该主题（`default` / `ios` 被拒绝，必须走模板新建） |

项目里存的是**主题目录的绝对路径**，所以主题在别的仓库（自己的项目）也能编辑。

## 界面

```
左上 文件列表（主题外观 / 页面视图 / 主题表）   中 预览区（选中什么渲染什么）   右 属性表
左   节点树（文件 → box → 每一层 → 每层字段 → states → 每状态 → 每通道）
左下 节点数 / 当前路径
```

- **预览区**：选「文件」渲染整个控件外观（真实控件类）；选「某一层」只画这一层
  （棋盘格底，方便看 shadow / 半透明）；选「某个状态」把该状态目标值归零时长后立刻到位；
  打开 `views/*.json` 时直接渲染**整页**（真实实例化那棵视图树）。
- **属性表**：按节点类型给表单（box 固定字段 / 层按 op 给字段 / states 的 to·duration·easing）；
  改任何一项立刻重建预览。数字和颜色都能写 `@theme/...` 引用。
- **保存**：先给 diff（哪个键从什么变成什么）→ 编译校验（不通过不写盘）→ 原子写 + `.bak` → 热重载。

## 操作效率（续）

- **把该字段套到其它层**：层字段行上的「套到其它层」按钮 → 弹层列出其它层（默认全勾，
  没有这个字段的层会标出来说"会新加"）→ 应用。`applyFieldToLayers()` 在 core 里，
  6 项测试（源层跳过、值相同不算改动、目标越界不崩、源层没这个字段返回 0）
  - 端到端实测：`button.primary` 的 5 层套 `radius` → 改了 4 个层，
    原来没有该字段的那层被新加上，保存后 5 层全一致
- **帮助弹层补全**：原来只写 F1 / F2，**漏了 F3**（跳到下一处改动）；现在补上 F3、
  数值框方向键、层复制/粘贴、改动打点这些后来加的

## 操作效率

- **数值字段支持方向键微调**：`InputScalar` 传了 step（±1）与 step_fast（Ctrl ±10）。
  以前 step 是 nullptr，方向键完全不动，微调只能全选重打
- **层的复制 / 粘贴（可跨外观）**：`复制层` 把整层放进剪贴板，切到别的外观 `粘贴层`
  会追加到末尾；`appendLayer()` 会自动把 id 改成唯一的（`bg` → `bg2`，再粘 → `bg3`），
  没有 id 的层不强行补。core 里有 10 项测试；
  端到端实测：复制 `rectangle` 的第 1 层 → 粘贴 → 存盘 → `ids = [bg, bg2]`

## 状态栏的"选中路径"面包屑 + 属性表改动清单

- 状态栏一行面包屑：`选中 <文件> / #N 层 / <字段>`，当前这一段用强调色；
  **前面的段可点**（点一下回到那一层），鼠标移上去变手形
- 属性表顶部一个可折叠的**改动清单**：列出所有未保存的改动路径，点条目直接定位
  （和 `下一处改动 (F3)` 互补：一个是"逐个跳"，一个是"直接点"）

## 改动的定位与"这一步改了什么"（补充）

- 属性表顶部有 **「下一处改动 (F3)」/「上一处」**：在未保存的改动里循环跳，
  状态行显示 `改动 2/2：layers[0].fill`；**Shift+F3** 反向；输入文字时不抢 F3
- 树头部三个开关：**全展开 / 只到层 / 只看层**（前两个只在点的那一帧生效，
  之后用户还能自己折叠 —— 用 `SetNextItemOpen(..., Always)` + 帧末复位实现）

**踩到的坑**：`refreshChangedPaths()` 原本拿 `viewTextApplied` 当缓存键，而它在某些路径上
还是空串、与初始值相同 → 函数直接早退，**改动集合永远是空的**（"下一处改动"报
"还没有未保存的改动"，属性表打点也会时有时无）。改成拿**文档自身的序列化**当键之后就稳了。
顺带把 `selectNextChange()` 做成"自己先刷新一次"，不依赖调用时机。

## 保存前的 diff：按"改在哪儿"分组

`groupChanges()` / `groupKeyOf()` / `groupLabel()`（core，9 项测试）：把改动按位置分组 ——

| 路径 | 分组 | 显示名 |
|---|---|---|
| `box.height` | `box` | 盒模型 |
| `layers[2].fill` | `layers[2]` | 第 3 层（1 起） |
| `states.focused.bg.fill` | `states.focused` | 状态：focused |

弹窗里每组一个可折叠节点（带条数）+「全部展开/收起」，组内每条**可点**（定位到那一处）。
弹窗定宽 820×430、列表是可滚动子区 —— 改动多时不会越长越高（最初没限高，
列表长了会把弹窗撑出屏幕）。

## 改动的定位与"这一步改了什么"

- `parseChangePath()`（core，11 项测试）：把变化路径解成"该选中哪里" ——
  `box.height` → box 字段、`layers[2]` → 整层、`layers[2].fill` → 层字段，其余归 OTHER
- **保存前的 diff 列表每条都能点**：点一下就把树/属性表定位到那一处
- **撤销 / 重做的状态行会说明这一步动了什么**：拿撤销前后两份文档比，
  列前 3 条路径（如 `已撤销：layers[0].fill`），撤销按钮的悬停提示也带上

自查钩子的**顺序有讲究**（踩过）：先把编辑做完（`EDIT` / `EDIT_DOC`），再 `UNDO` / `REDO`，
最后才 `FORCE_SAVE` / `SHOT`。之前 `EDIT_DOC` 排在 `UNDO` 后面，验证出来的撤销说明
少了一条 —— 从日志顺序一眼能看出来。钩子里也补了 `EDIT_DOC` 成功/失败的日志。

## "一眼知道改了什么"

- `designer/core/diff.*` 新增 `changedPaths(before, after)`：返回**变化的叶子路径集合**
  （`box.height` / `layers[0].fill` …），4 项测试
- 属性表里**改过的字段前面点一个强调色圆点**（和"磁盘上那份"比，`savedText` 就是磁盘态）
- 树里**改过的层**那一行同样带点
- 预览面板标题变成 `未保存 · 改动 N 处`
- 每帧只在文档真的变了时重算（用 `viewTextApplied` 当缓存键）

自查钩子 `BKLV_DESIGNER_EDIT_DOC` 现在支持 `layers[0].fill=#FF8800` 这种带下标的路径
（之前只认对象键）；带 `[` 但格式不对会当场拒绝，不会把文件写坏。

## 层序条（预览左侧）

按绘制顺序列出各层，每行一个色块：

- **不透明层**画成它自己的颜色（`fill` 解 `@theme/...` 或 `#RRGGBB[AA]`）
- **透明/半透明层**画成**棋盘纹**（和预览画布的"网格底"一个意思）——
  直接画一块淡色看不出"这层是透明的"；半透明再叠一层自己的颜色，能看出色偏
- 选中的层高亮；点一下就选中那层，和树 / 属性表联动
- 色块占左侧栏位，标签用 `    #N op` 留出位置（`Selectable` 的文字从光标处开始，
  不腾位置色块会被压住 —— 第一版就是这样）

## 自查纪律（每轮都做）

"上一轮的功能到底生效没有"要**当场验证**，不能只看代码写完就报完成。这轮就是这么抓到两个 bug 的：

- **"只看层"没生效**：`TreeNodeFlags_Leaf | NoTreePushOnOpen` 下 `TreeNodeEx` 返回的 `open`
  **恒为 true**，子块照跑 → 字段没被隐藏 ✗
- **同一个根因还带出 ImGui 断言** `Calling PopID() too many times!`（每层报一次）：
  子块里调的 `TreePop()` 在 `NoTreePushOnOpen` 模式下等于多调一次 `PopID`

修法：`if (open && !this->onlyLayers)`。教训：用 `Leaf|NoTreePushOnOpen` 就必须
**完全跳过**子块，不能只靠 `open` 判断。

## 面板可拖 + 界面整体缩放

用户反馈的问题（都已修）：

1. **三栏宽度是写死的**（`leftWidth=320` / `rightWidth=420`，`BeginChild` 固定宽），
   **没有分隔条** → 拖不动。现在左栏 / 右栏之间、左栏里"文件列表↔节点树"之间
   都有分隔条：悬停变左右（上下）箭头并高亮、拖动改宽度、**双击复位**，
   拖完存进 `designer_state.json`。宽度都用 `clampPanelWidth()` 钳住，
   保证两侧都留得住内容（窗口太窄时优先保下限）
2. **没有界面缩放控制** → 屏幕大或 Retina 下界面显得偏大。现在顶栏右侧有
   `界面 75% / 85% / 100% / 115% / 130%`：同时作用于**字体**（`style.FontScaleMain`）
   与**所有间距/控件尺寸**（样式函数里按 `uiScale` 重算，幂等，不用维护"原始尺寸"副本）。
   **默认 0.85**（按 ImGui 默认字号 + Retina 逻辑分辨率，1.0 偏大）

两个坑：

- **分隔条是个 ImGui item，画完光标会换行** → 后面必须再 `SameLine()`，
  否则中间/右栏被推到看不见的地方（第一次改完就是这个现象：只剩左栏）
- 工具栏宽度检测用 `GetCursorPosX()` 量不准（那位返回行首）→ 改用
  **上一个控件的右边缘**（`GetItemRectMax()`）来判断要不要换行；
  换行点在**整组之前**，否则会把一组按钮拆到两行（撤销/重做被切掉就是这原因）

## 视觉规范（改界面时照这个来）

- **配色跟着主题走**：`designer/ui/designer_style.*` 读当前主题的语义色
  （`color.surface.*` / `color.text.*` / `color.border.*` / `color.accent.*`），
  换主题 / 热重载后设计器自己也换色。取不到就用内置默认值兜底
- **注意键要带 `color.` 前缀**（加载时就是这么展平的）；漏了会静默退化成 fallback
- **`applyDesignerStyle()` 要先判 ImGui 上下文**：`attach()` 早于第一帧，
  没上下文时 `GetStyle()` 直接踩空（崩过一次）
- 统一：圆角 6px（子窗口 8px）、`ItemSpacing 8/6`、`WindowPadding 12`、
  面板标题走 `panelHeader()`（抬起的标题条 + 左侧强调色竖条）
- 顶栏按功能分组，组间用 `groupBreak()`：**里面不能用 `Dummy`** —— 那会让光标换行、
  顶栏被拆成好几行（试过一次）
- 属性表统一"标签左列（172px）+ 控件占右侧"；未写的字段用暗色 `·` 标出，
  不要把"（未设置）"塞进标签里（会把标签撑爆、右边被裁）

## 从任务倒推：一次"改样式"要走几步

设计界面之前先把用户的真实任务拆开（这是评审这套界面流程的依据）：

| 任务 | 理想步骤 | 之前的问题 |
|---|---|---|
| 打开一个项目 | 选 `theme.json` → 打开 | 要**手输主题根目录 + 主题名**，写错也不知道错在哪 |
| 找到要改的控件 | 搜名字 → 点开 | 43 个外观靠滚动；树的字段默认全展开挤成一团 |
| 改一个属性 | 选中层 → 在属性表改 | 层操作（上下移/复制/删除）以前要先选中层再去右边点按钮 |
| 看效果 | 就在旁边 | 以前预览经常被裁；画布尺寸要手填 |
| 存下来 | 一次保存 | 以前没有 diff / 冲突检测 / 增量写盘 |
| 反悔 | Ctrl+Z | 撤销栈以前写在 UI 里、**重做实际不可用** |

**已经落地的（按任务分）**：

| 任务 | 已做的优化 |
|---|---|
| 打开项目 | 文件浏览器（选 `theme.json`），不再手输路径 |
| 找控件 | 文件列表带搜索 + **最近修改**快捷区 + 每个控件标 `●` 未保存；树里有**全展开 / 只到层 / 只看层**；属性表有**「下一处改动 (F3)」** |
| 改属性 | 属性表按分组 + **字段过滤框**；标签左列对齐、未写字段用暗色 `·`；层操作就在层那一行 |
| 看效果 | 画布居中、**自适应时挑一个铺满预览区的缩放**、**画布左侧的层序条**（按绘制顺序列出各层、带色块、点一下就选中那层）、网格/中线可切 |
| 存 | diff → 校验 → 增量写盘 + `.bak` → 热重载 |
| 反悔 | Ctrl+Z / Ctrl+Y（撤销栈在 core，有测试） |

结论（最初按这个改）：

1. **打开项目必须是文件浏览器**，不是手输路径 —— 两种模式（模板新建 / 直接编辑）
   都从 `theme.json` 选起，选完自动推出主题名与主题根
2. **找控件**：文件列表带搜索（已有）+ 分组计数；树只展开到"层"，字段按需展开
3. **改属性**：属性表按"常用 → 布局 → 颜色 → layers"分组，标签左列对齐，
   **层操作就在层那一行**（不用先选中再去右边点）
4. **看效果**：预览占中间最大块，画布控制收进一行，选项进"视图"下拉
5. **存/反悔**：顶栏只留主操作（保存 / 撤销 / 重做 / 校验），其余进菜单

## 快捷键与几个界面约定

| 键 | 作用 |
|---|---|
| Ctrl+S | 保存（先弹 diff） |
| Ctrl+Z / Ctrl+Y | 撤销 / 重做（帧级快照，最多 64 步） |
| Ctrl+D | 复制当前层 |
| Alt+↑ / Alt+↓ | 上移 / 下移当前层 |
| F1 | 校验面板（整主题校验 + 层序提醒） |
| F2 | 预览最大化 |
| 滚轮 / 中键（或 Shift+左键） | 画布缩放 / 平移 |

- **多文件同时改**：每份打开的文件的编辑状态都留着（草稿），切文件会拦截未保存改动
  （保存并切换 / 丢弃 / 取消）；「改动总览」列出所有脏文件并可一键全部保存

- 两处没做到位的：整页预览里**覆盖高亮**选中节点（需要库导出 JSON↔视图节点映射）、
  保存仍是整文件重写（键序与 `$` 元信息保住，写前 diff + 冲突检测 + `.bak`）

## 预览里的"对着看"

- **选中树节点 → 预览里框出来**：库里 `createFromJSONString(json, &map)` 会导出
  "JSON Pointer ↔ 视图指针"的映射，设计器拿它读该节点的 `getFrame()` 画框（带路径角标）
- **点预览 → 反选节点**：在映射里找"包含点击位置、面积最小"的那个节点，选中它并展开左树
- **焦点顺序**：按视图树顺序列出可聚焦控件，可在预览里打 1 2 3…（导航顺序大致就是这个）
- **对比度检查**：文字层颜色与控件底色的对比度 < 4.5:1 时进校验面板提醒
- **日志面板**：设计器自己的 ImGui 面板（读库里的 `Logger` 环形缓冲），顶栏「日志」开关
  —— 库侧不再提供 ImGui 版日志窗口，app 里的日志界面是视图树里的 `DebugLogView`

## 第 11 轮补的

- **状态通道的默认值按属性类型给**（core `defaultChannelValue`）：颜色类属性给颜色串、
  数值类给合适的数。以前所有新通道都是 `to: 0.0`，颜色通道一加就编译失败
- **另存为变体**：把当前外观（含未保存改动）复制成一个新外观并登记 —— 做变体最常用的工作流。
  core 那条 `createWidgetAppearance` 负责重名检查 + 登记 + 落盘回滚，写盘前先编译校验
- 自查钩子补 `BKLV_DESIGNER_VARIANT=<新名>`（实测：变体文件生成、`theme.json` 登记成功、
  外观总数 43 → 44）

## 第 15 轮：include 缓存 + 两处"只读/悬垂"边界

- **`include` 展开不再每帧读盘解析**：视图树里展开一个 `include` 时，
  以前每帧都要读文件 + 解析（展开一个就够拖帧率）。新增 core 的 `JsonCache`
  （同路径只读一次、失败也缓存、`clear()` 后重读），8 项测试；
  保存/重载后会 `clear()`，被包含的文件刚改过也能看到
- **切到主题表没清绑定/映射** → 焦点顺序面板里会留着上一份的 `View*`（重建后悬垂）。
  补上 `openTableFile` 的清空
- **「全部保存」的只读判断过宽**：`if (readOnly) return;` 把**可编辑的页面视图**也挡了。
  改成按文件类型逐份判断：只读主题只挡主题文件（外观 / 主题表），页面视图照常可存。
  **实测**：在只读的 `default` 下走「全部保存」，页面视图确实被写进去了

## 第 14 轮：修好"全部保存"（主题表根本存不进 + 绕过冲突检测）

自审 `saveAllDirty` 抓到三个缺陷：

1. **主题表根本存不进**：以前靠"先试实例化、失败再试编译"猜文件类型，
   主题表两种都失败 → 只留一条警告就跳过。现在新增 core 的
   `classifyThemeFile()`（外观 / 页面视图 / 主题表 / 未知）决定校验方式
2. **绕过了冲突检测**：它直接 `writeTextFileAtomic`，磁盘被外部改过也照写。
   现在和单个保存一样走 `writeFileChecked`（被挡住的文件跳过并报出来）
3. **未应用的页面文本会被漏掉**：先 `applyPendingViewText()` 再遍历

**实测**：fork 一个主题 → 改 `common.red = #FF0000` → 「全部保存」→
文件里确实是 `#FF0000`（改前这一步是静默跳过的）。

新增自查钩子：`BKLV_DESIGNER_SAVE_ALL` / `BKLV_DESIGNER_EDIT_DOC=<点分路径>=<JSON 值>`。

> 过程教训：这轮我两次用"从函数 A 到函数 B 之间整段替换"的方式改代码，
> 结果把夹在中间的 `requestSave` / `doSave` 等函数一起削掉了（链接期才发现）。
> 改成**按大括号配对**定位函数体之后再替换；`git checkout` 兜底也只用了两次。

## 第 13 轮：撤销栈进 core + 修好"重做其实用不了"

- **撤销栈抽进 core**（`designer/core/undo_stack.*`）：连续相同不重复入栈、撤销后重做、
  新改动断掉重做链、超过 64 步丢最老的 —— 13 项测试。以前这段逻辑直接写在 UI 里，没有覆盖
- **修好一个真 bug：重做实际用不了**。撤销/重做之后没同步"上一帧内容"，
  下一帧边界会把它当成"又改了一次"再压一步，而 `push()` 会清空重做链 → 重做永远失效。
  修完**实测**：改 `height=64` → 撤销（保存判定"内容没变"）→ 重做 → 保存 → 文件是 `height: 64`
- **「复制 JSON」按钮**：复制当前选中节点那一段（选中层→该层；选中 box→box；否则整份）
- 自查钩子补 `BKLV_DESIGNER_UNDO` / `BKLV_DESIGNER_REDO`。
  踩到的顺序问题：钩子在任何一帧之前跑，所以它自己补一次压栈 —— 而且必须"先改再压"
  （压"改前"的内容会被去重逻辑跳过，撤销就没东西可撤）

## 第 12 轮：定位并修掉那条 spurious 警告

上一轮记的 `主题颜色缺失：button.primaryText` 定位到根因了，**是设计器自己的 bug**：

- 主题加载时把 `colors.json` 展平成**带 `color.` 前缀**的键（`color.button.primaryText`），
  而外观里可以省前缀写 `@theme/accent.base`
- 设计器查表时**把 `color.` 前缀剥掉了** → 一直在查不存在的键 → 色板取到 fallback、
  **对比度检查也整个失效**（查空 → 拿 fallback 当底色算）
- 修法：新增 `designer/core/theme_key.*` 的 `themeKeyFromReference()` 做统一归一
  （补前缀、斜杠容错、非 `@theme` 引用返回空串），设计器三处查表全走它；测试 5 项

顺带两件事：

- **缺键警告带上现场信息**（当前主题、已装载色数、同前缀的已装载键），
  就是这条诊断信息把根因照出来的；把"两个颜色表都是空的"这种情况单独点明
  （那是"主题还没装载"，不是 key 拼错）
- **对比度检查的底色取法修正**：改成"文字层之前最后一个不透明 rect 层"，
  比以前只看 `box.backgroundColor` 准得多。修好后与独立算的数完全一致：
  `dropdown/title` 3.2:1、`account/initial` 3.8:1 —— **这两个是主题里真实偏低的**
  （正文建议 ≥ 4.5:1）

- **主题表保存后的影响清单**：这次动到的 key 影响了哪些外观，写进状态行与日志
- **编辑主题表时旁边保留预览**：主题表没有自己的预览，就用"最近打开的那个外观"
  （保存后主题热重载，再建一次就能看到新颜色）
- 自审/自查钩子抓到的四个缺陷：
  1. **页面视图的文本改了没点「应用」→ 保存时静默丢掉**。两条保存路径
     （`requestSave` / `doSave`）现在都会先自动应用一次，校验不过就不写
  2. **页面视图保存后草稿脏标记没清** → 文件列表一直挂着 `●`、改动总览里也留着
  3. **只读基准主题把页面视图也挡住了**：视图在 `resources/views/` 下，不属于主题，
     应该照常可改（只读只保护主题文件）
  4. 新建/删除外观后没刷新 `themeUsage`（引用关系会过期）
- 自查钩子补 `BKLV_DESIGNER_EDIT_TEXT=<JSON>`：改页面视图的**文本缓冲但不点应用**，
  用来验证上面第 1 条真的生效（实测：保存后文件里是新内容，且增量写盘只替换了变化的段）

## 第 8 轮补的

- **主题 key 的反向引用**（主题表里）：每一行显示"· N 处引用 / 没被引用"，
  点「谁在用」列出引用它的外观、点一下切过去。改配色前先知道会动到谁；
  "没被引用"的键是死配置，一眼可见
- 自审修的两个问题：
  1. **切换文件后没清绑定/映射**：焦点顺序面板会留着上一页的 `bindings`，
     那些 `View*` 在预览重建后就悬垂了（use-after-free）→ 换文件时清掉
  2. 「套用示例数据」以前**直接碰视图指针**：改成置标记、等"建完预览之后"再套，
     这条路径上的指针一定是新的；示例数据也按文件各自保存，不串页
- 截图抓到的 bug：主题表里的键是 `radius.md`（文件里没有 `metric.` 外层），
  而引用是 `@theme/metric.radius.md` —— 查表时没补前缀，导致**全部显示"没被引用"**

## 第 7 轮补的

- **数据绑定示例数据**：页面有 `bind` 时，预览里那些字段本来没有数据源（列表/文字全空）。
  现在打开页面会自动生成一份示例数据（`字段 → 示例 xxx`），面板里可编辑 +「套用示例数据」
- **切主题也会拦未保存改动**：切主题要清草稿，之前是静默丢；现在走同一个拦截弹层
  （保存并切换 / 丢弃 / 取消）
- 库侧新增 `applyViewAttribute(view, name, value)`：用字符串值泛化套一个属性
  （复用实例化 JSON 那条路：类型转换、`@theme` / `@i18n`、枚举宽容都在里面）；
  未知属性返回 false（`NOT_HANDLED` 不等于 APPLIED）

## 第 6 轮补的

- **主题切换器**：顶栏下拉直接切 `themes.json` 里的主题（基准主题只读浏览）；「设为默认」
  写 `themes.json` 的 `default`（只读主题不给改）
- **`include` 在树里展开**：`[include] <路径>` 节点展开成被包含文件的树（递归有上限）
- **数据绑定列表**：焦点顺序面板里列出"哪个节点绑了哪个字段"（预览里没有数据源，
  绑定出来的内容是空的 —— 面板里写着）
- **缩放提示更准**：画布不是 1280 宽时给「按真机 720p 画布」一键切换（主题尺寸都按 1280×720 写）
- 树里的角标换成 ASCII（`[bind x]` / `[include x]`）—— `⟲`/`⤵` 这类字形字体里没有，会画成 `?`

## 这一轮补的

- **枚举字段给下拉**：层的 `align` / `valign` / `scaling` / `axis` / `direction` 不再手打；
  `fontSize` 列出主题里的字号 key，`source` 列出可用槽位（也都能手写）
- **按约定重排层序**：层序提醒旁边给一个按钮（shadow → 底色 → hlBg → 内容 → hlGlow/hlBorder），
  只动顺序不改字段，Ctrl+Z 可撤
- **新建页面视图**：空页面 / 整页（页头+内容+底栏）/ 卡片，写盘前先试着实例化
- **`bind` / `include` 看得见**：树里节点带 `⟲ bind` / `⤵ include` 角标；页面有绑定时
  预览栏提醒"预览里没有数据源，绑定出来的内容是空的"
- **JSON 页面能用控件类型**（见 `docs/json-syntax.md`）：`Button` / `Rectangle` / `Shell`
  （旧的类型名 `AppletFrame` 仍然可用 —— 内部构造的就是 `Shell`）
  / `Header` / `BottomBar` / Cell 家族等已注册，App 启动时自动注册

## 写在明面上的"没做到位"

- 保存是**整文件重写**（键序保住、缩进沿用原文件、内容没变就跳过、写前 diff + 冲突检测 +
  `.bak`），但不是真正的"只改那两行"
- 焦点顺序按**视图树顺序**近似（真机导航还受可聚焦性与模态影响），不是逐步模拟出来的

## 两条踩过的坑

- **ImGui 默认字体必须显式设**（`bklv/core/font.cpp` 的 `setDefaultFont` 会设
  `io.FontDefault`）。不设的话 ImGui 用字体表里的第 0 个，而那可能是先加载的
  **图标字体**（只有私用区几个字形）→ `ImGui::Text` 什么都画不出来，
  而 bklv 的文本没事（它自己传字体）。日志窗口/设计器都靠这条。
- **截图按帧缓冲读取**（`App::saveScreenshot` 用 `io.DisplayFramebufferScale`）：
  Retina 上帧缓冲是逻辑尺寸的 2 倍，按逻辑尺寸读只会拿到左下角那块，
  截出来的图是被放大的局部。
