# 分层外壳与焦点管理（设计讨论稿）

> 状态：**讨论稿，尚未实现**。这里记录与用户逐轮讨论后确定的方案、审查结论与待定项。
> 讨论时间线：AppletFrame 三段式 → 四层分层 → 焦点层级切换 → 层内导航规则。

## 1. 为什么改：三段式的限制

现在 `AppletFrame : Box(COLUMN)`，`header / contentBox / footer` 三个兄弟
（`widgets/applet_frame.cpp:15-40`），内容区由 Yoga 自动避让页头底栏。问题：

- 内容被限制在中间那条带子里：封面大图铺不到状态栏下面、转场元素飞不过页头；
- 背景（图片，后续视频）无处安放；
- 弹窗/toast/焦点指示没有明确的绘制层级。

## 2. 四层结构（已确认，**旧 AppletFrame 设计可放弃**）

```
Shell（取代旧 AppletFrame 的位置）
├─ BackdropLayer   背景层   绝对定位，全屏或指定坐标；**只支持图片**，视频后续再说
├─ ContentLayer    内容层   Yoga 根；页面栈 / 路由都在这
├─ OverlayLayer    覆盖层   Yoga 根；**页头、底栏、弹窗**都在这里
└─ HudLayer        浮层     绝对定位，不吃输入；**焦点指示**、toast、跨层飞行的临时元素
```

命名理由：原提议的 `PopFrameLayer` 容易被理解成"弹窗层"，而弹窗按新划分在覆盖层；
`HudLayer`（抬头显示）更贴合"瞬时、不吃输入、总在最上"的定位。备选 `FloatLayer`。

### 层的规则

| 规则 | 内容 |
|---|---|
| 绘制顺序 | 背景 → 内容 → 覆盖 → 浮层（后者盖前者） |
| Yoga | 只有**内容层**与**覆盖层**参与重排；背景层、浮层绝对定位不参与 |
| 焦点 | **只在内容层与覆盖层之间切换**（背景层、浮层不参与） |
| 模态 | 用**挂载标记**（`pushModal` / `modalityRoot`）表示，**不用层号判断** |
| 内容避让 | **不自动**：页面显式调用 `getHeaderInsets()/getFooterInsets()` 决定留白 |
| 坐标 | 跨层读 `View::getFrame()`（`core/view.cpp:413` 就是**绝对坐标**），不做换算、不重排 |
| 层尺寸 | 绝对层跟随视口尺寸（要挂"画布尺寸变化"的通知，否则改窗口后尺寸不同步） |

### 一个待定决策

`App::pushOverlay()` 现在把弹层挂在 **root 之上**（比浮层还高），与"弹窗在覆盖层、
toast 在最上"矛盾。二选一：
1. shell 提供 `pushDialog()` 挂到覆盖层顶部（推荐），`App::pushOverlay` 留给系统级全屏模态；
2. 或者让浮层也移到 App 之上（不推荐）。

## 3. 焦点管理（本轮讨论）

### 3.1 跨层切换（内容层 ⇄ 覆盖层）

需要一个切层函数，语义：

- **内容层 → 覆盖层**：覆盖层**显示完成后**再切焦点 → 先 `remember()` 保存当前焦点，
  再取覆盖层的默认焦点；
- **覆盖层 → 内容层**：关闭**开始**时就恢复 → `restore()`；
  **若原焦点已不存在 → 退到内容层的默认焦点**。

时序与库既有约定一致：`applet_frame.hpp:62` 写着"转场期间焦点先不挪，等落位再给新页"；
关闭时视图要"等动效播完再摘"。所以：**开始关闭就恢复焦点，动画结束才摘视图**。

### 3.2 需要的三项能力

1. **获取默认焦点**：`getDefaultFocus()` 链（库已把 `getDefaultFocus` 列为子类扩展点）
2. **记录/恢复焦点**：建议做成**栈**（弹窗套弹窗、详情页下钻都要一层），
   并且记录的是**路径 + hint**（层 / 页 id / 控件路径 / 上次索引），
   **不要存裸 `View*`** —— 页面可能已被换掉销毁（本项目踩过悬空指针）
3. **补救**：恢复时校验存在性；不存在 → 层默认焦点；层也没默认焦点 → **保持当前焦点不变、
   但把输入路由给模态**（不能让当前焦点变成 null，否则方向键乱）

### 3.3 层内导航规则（用户提案 + 审查）

- 只有 **可聚焦 && 非禁用 && 在树里可见**（可见性要**沿父链**判断）**&& 未被模态遮挡** 的元素能获得焦点
- 同一 Box 内**依次向下冒泡**；Box 的 `axis` 决定主轴方向（row → 左右，column → 上下）；
  交叉轴方向用于跨 box；四方向共用同一套几何判定（**最近邻，不是索引顺序**）
- **跨 box 导航开关**：默认**允许**；建议三档且局部生效（设在 box 上、影响其子树、内层可覆盖）：
  - `ALLOW`（默认）：可以导航到同级/父级同级
  - `SAME_PARENT_ONLY`：只在本 box 与其子 box 内走
  - `NONE`：出不去，需要显式出口

### 3.4 审查提出的四个补充

1. **保存的是路径不是指针**（见 3.2-2）
2. **模态要同时约束同层其它子树**：否则方向键会跑到被弹窗遮住的页头/底栏上
3. **"没有默认焦点"必须单独处理**（见 3.2-3）
4. **`focusable` / `disabled` / `visible` / `reachable` 是四个独立条件**，规则写成
   `canFocus = isFocusable() && !isDisabled() && isVisibleInTree() && isReachableFromModal()`

### 3.5 焦点框绘制

- **唯一真相**是 FocusManager 的 current；浮层只是读者
- 控件自带的 `hlBg / hlGlow / hlBorder`（focused 状态的外观层）**保留** —— 它是外观的一部分，
  主题可以逐控件调参；浮层只放**跨层/临时**指示（toast、跨层飞行元素、无外观控件的通用焦点圈）
