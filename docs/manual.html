概览

bklv 是一个跨平台 C++17 界面库：Yoga 算 Flexbox 布局，ImGui 的 ImDrawList 负责绘制。 目标形态是能被外部项目 add_subdirectory / find_package 引入的库，本仓库同时提供一组示例程序（examples/）。

项目内容
平台macOS / Linux / Windows（SDL3）、Nintendo Switch（libnx + EGL/GLES3）
图形后端OpenGL 3.2 Core、Vulkan、OpenGL ES 3（编译期选择，所有功能都要双后端验证）
主题两套：default（纯扁平）与 glass（玻璃质感；缺项逐键回退 default）
界面描述C++ 建树，或 JSON 视图描述（template / instantiate 两段式）
不做XML 布局与绑定、视频、PS4/PSV（音频只做音效：JSON 音效表 + WAV，不做 BGM/流式播放）

库的代码规模（不含 3rd/ 第三方）：core/ 28 文件、geom/ 2 文件、paint/ 6 文件、anim/ 5 文件、json/ 6 文件、theme/ 20 文件、layer/ 8 文件、view/ 10 文件、app/ 4 文件、media/ 15 文件、input/ 8 文件、render/ 36 文件、platform/ 9 文件、widgets/ 42 文件。

禁止的方向（scripts/check_layers.py 逐对检查）：core 不许碰 theme / layer / view / app / widgets； json / media / render 同上；theme 不许碰 view / app / widgets； layer 不许碰 view / app / widgets；view 不许碰 app / widgets； platform 不许碰 theme / layer / view / widgets。存量 4 条反向依赖记在 BASELINE 里 （白名单必须精确：消解一条就要删一行，脚本会报"白名单已过期"）。

两条机械门禁

  • python3 scripts/check_naming.py —— 枚举值 UPPER_SNAKE、类型 PascalCase、方法/自由函数 camelCase、布尔开关 set<名词>Enabled、状态查询 is*/has*/can*。
  • python3 scripts/check_layers.py —— 禁止新增反向依赖；另外查伞头可达范围： bklv/bklv.hpp 顺着 include 不许碰到具体后端（render/vk/、render/gl/、 render/gles3/、render/libnx/、render/glass/{gl,vk}/）、platform/ 或 <vulkan/vulkan.h>。

全局状态（core/globals.hpp）

进程级状态只有一处登记：bklv::globals::getGlobalStore()。对象槽分"拥有（obtain 懒创建 / set owned）"与 "借用（App、平台、后端）"，另有数值槽（number / flag / text）与重置钩子；resetGlobals() 一轮清干净。 已登记：EventBus、InputManager、当前 App、玻璃服务，以及纹理仓库与四条注册表的重置钩子。 库仍是单实例（一个进程一套界面、全局 ImGui 上下文）。

构建与运行

# GL 版（产物到 dist/）
cmake --preset gl && cmake --build --preset gl

# Vulkan 版（产物到 dist/vk/，需要 Vulkan SDK / MoltenVK）
cmake --preset vk && cmake --build --preset vk

# 一次跑完所有门禁（命名 → 分层 → GL/VK 双后端零警告构建）
bash scripts/check.sh

约定：-Wall -Wextra -Wpedantic 零警告；每个后端各一个构建目录、产物分目录（dist/ 与 dist/vk/）。 CI 一个平台一份 workflow（.github/workflows/，都只编 GL）：static.yml（命名 / 分层）、 linux.yml（ubuntu + GCC）、macos.yml（AppleClang）、 windows.yml（MinGW 一个 job、MSVC 一个 job）、switch.yml（devkitpro/devkita64 容器）； 都走 scripts/ci_build.sh gl，构建出现 warning 即失败。Vulkan 版本地验（scripts/check.sh）。

用到自己的项目里

add_subdirectory(third_party/bklv)
target_link_libraries(my_app PRIVATE bklv::bklv)

#include "bklv/bklv.hpp"
auto* app = new bklv::App();
app->setRootView(new bklv::Box(bklv::Axis::COLUMN));
app->run("我的应用", 1280, 720);

包含路径不用自己加：bklv::bklv 会把 bklv/ 的父目录带出来，所以直接写 #include "bklv/app/app.hpp"。图形后端是编译期决定的（-DBKLV_GRAPHICS=gl|vk）。

接口速查

bklv 速查

bklv/ 是从 borealis（Apache-2.0，wiliwili 使用的框架） 移植过来的视图层。这份文档是写代码时的速查表：文件职责、常用调用、以及踩过的坑。

设计上跟 borealis 保持一致：没有独立的渲染树，一个 View 持有一个 YGNode， 布局由 Yoga 递归计算，绘制由 View::draw 递归完成。

绘制后端从 NanoVG 换成了 ImGui 的 ImDrawList，并按需砍掉了这次用不到的 阴影、渐变、焦点高亮、点击动画、XML 布局和平台抽象层。

Box* box = new Box(Axis::ROW);          // ROW 横向 / COLUMN 纵向
box->setPadding(16.0f);                  // 内边距，也支持 4 边分别设置
box->setGap(14.0f);                      // 相邻子节点间距

box->setAlignItems(AlignItems::CENTER);  // 交叉轴对齐
Box* child = new Box(Axis::COLUMN);
child->setDimensions(90.0f, 90.0f);      // 固定尺寸
child->setGrow(1.0f);                    // 或按比例分配剩余空间
child->setShrink(0.0f);                  // 固定宽度不被压缩
child->setMargin(8.0f);                  // 外边距
box->addView(child);

视图树管理：addView(view[, position])、removeView(view, free)、clearViews()、 getView(id)。增删子节点时 children 与 Yoga 节点树必须同步更新， 否则布局结果会和 C++ 对象树不一致；子节点析构时会自动从父节点摘除。

文案（i18n）

资源放 resources/i18n/<locale>.json，key 用 / 分层：

{ "demo": { "welcome": "欢迎使用 bklv", "list_count": "共 {} 项" } }
bklv::translate("demo/welcome");              // "欢迎使用 bklv"
bklv::translate("demo/list_count", 12);       // "共 12 项"（{} 按顺序替换）
bklv::translate("demo/nope");                 // 未命中返回 key 本身
bklv::translate("demo/list_count", 12);       // 带占位符必须用函数形式
"demo/welcome"_i18n;                          // 无参数 key 的字面量写法（需 using namespace bklv::i18n）
"demo/list_count"_i18n(12);                   // 带参数：占位符 {} 按顺序替换
"demo/welcome"_i18n.str();                    // 显式取字符串（auto 存下来就是 key 包装，不是 string）
bklv::setLocale("en-US");                  // 运行中切换
bklv::getLocale();                         // 规范化后的当前语言

三条要记住的：

  1. 文案在控件构造时就解析成字符串，改语言不会自动重译已有视图——

要重新 setText() 或重建视图树（宿主里那个 「切换语言」按钮演示了显式重译）。

  1. 语言名是规范化的（zh-Hans / zh-Hant / en-US / ja-JP / ko-KR）。

桌面 SDL 给的是 zh-CN、Switch 给的是 zh-Hans，都经 canonicalLocale() 归一， 所以资源文件只需要一套命名。

  1. 不依赖目录枚举：按名字读 <locale>.json；要拆文件就在主文件里写

"$files": ["hints.json"] 清单（romfs 上的目录迭代真机未验证，所以不扫描目录）。

initI18n() 在 App 构造时调用，早于视图树构建；也可以在测试里单独调 setLocale()，默认语言表是懒加载的。

JSON 视图描述

用 JSON 描述界面，运行时装成视图树。属性直接平铺在节点上，特殊键只有四个 （type / children / include / bind）：

{
  "type": "Box", "axis": "row", "gap": 12, "padding": 12,
  "backgroundColor": "#252a33", "cornerRadius": 10,
  "children": [
    { "type": "Image", "src": "@res/testcard.png", "width": 96, "height": 54,
      "cornerRadius": 8, "scalingType": "fill" },
    { "type": "Label", "text": "@i18n/json/card_title", "fontSize": 16, "singleLine": true }
  ]

bklv::View* view = bklv::createFromJSONFile("resources/views/page_json.json");
if (view != nullptr)
    box->addView(view);           // 失败时返回 nullptr，原因已在日志里

值可以写原生 JSON 类型，也可以写带单位的字符串： 24 与 "24px" 等价，"50%" 走百分比，"auto" 由内容决定，true/false 是布尔。

四条要记住的：

  1. 两段式。ViewTemplate 是可缓存的"解析结果"，instantiate() 才把 @i18n/

这类上下文相关的前缀解析掉。同一模板实例化多次只解析一次 （resources/views/list_item.json 被 8 个 cell 共用）。

  1. 路径写全：createFromJSONFile("resources/views/x.json")——和图片一样带 resources/

这一层（桌面解析到可执行文件目录，Switch 在 romfs）；属性里的 @res/x 则相对 resources/ 目录。

  1. 出错不会崩：语法错误带行号、结构错误带 json_pointer 路径，都返回 nullptr；

未知属性只是警告并提示最接近的属性名。多打一个键不会让整个界面建不出来。

  1. 新控件要能被 JSON 用，重写 attributes() 返回一张静态表即可；公共属性

（尺寸/间距/定位/外观/可见性）在 View 层已经都有。

列表项模板配合数据绑定（JSON 只管字段名，取值在 C++ 侧）：

{ "type": "Label", "bind": "title" }
auto tmpl = bklv::ViewTemplate::load("resources/views/list_item.json");
list->registerCell(bklv::RecyclerDataSource::DEFAULT_CELL_ID, [tmpl] {
    return bklv::JSONRecyclerCell::create(tmpl, [](const std::string& field, size_t index) {
        if (field == "title") return titles[index];
        return std::string();
    });
});

bind 的默认目标属性：Label → text，Image → src；其他类型要显式写 bindTo。

布局与失效

布局是延迟的：View::invalidate() 冒泡到根只是标记"要重算"，真正的一次 YGNodeCalculateLayout 发生在 App::frame 里，一帧最多一次。

触发条件谁来触发
视图改了（setText / setWidth / addView / …）各 setter 内部 invalidate()
画布尺寸变了App::frame 自己比较上一帧尺寸
首帧App::frame 初始化时就是脏的
影响布局的全局状态变了（如切换 Style）你自己调 App::requestLayout()
bklv::App::requestLayout();        // 请求下一帧重算
bklv::App::getLayoutCount();       // 累计布局次数（调试窗口状态行里也有）

不要在改了布局相关属性之后、同一帧内立刻读 getWidth()/getHeight() —— 新值要下一帧才生效。回收器不受这条影响：cell 的位置是用 setTranslation 摆的， 与 Yoga 无关。

界面不刷新时先怀疑"漏置脏"：用 BKLV_FORCE_RELAYOUT=1 跑一次，退回每帧全量重算， 现象消失就说明有地方改了布局状态却没 invalidate()（或该用 requestLayout()）。

四类 JSON（视图描述 / 控件外观 / 主题 / 文案）的完整键表、取值形式与枚举拼写， 见 json-syntax.md。

阴影（"op": "shadow"）

阴影是一种层，写在自己的底色之前就先画阴影（theme_test 会断言这个顺序）：

"layers": [
  { "op": "shadow", "id": "shadow", "fill": "@theme/color.shadow.base",
    "feather": "@theme/metric.shadow.feather",   // 羽化半径
    "radius": "@theme/metric.shadow.radius",     // 圆角（会跟着外扩一起长）
    "offset": [0, "@theme/metric.shadow.offsetY"], // 位移：正 y = 往下方投影
    "spread": 0 },                               // 额外外扩（负数可收紧）
  { "op": "rect", "id": "bg", "fill": "@theme/color.surface.card", "radius": 12 }
]
  • "cutout": true（可选）：把控件自身圆角形状挖掉，只画外圈（沿中线描一圈实现）。不开时阴影是垫在控件下面

的一整块——底色若是半透明就会透出阴影；开了之后内圈不画，后面加的层哪怕是透明色也干净 （borealis 的 nvgBoxGradient + NVG_HOLE 就是永远这么做）

  • fill 的 alpha 就是阴影浓度；opacity、feather、spread、offsetX/offsetY 都能进

states 做动效（例如聚焦时 "shadow.opacity": { "to": 0.7 }）

  • 绘制档位是全局开关，两种都是多层近似：fast（8 层，默认）/ smooth（24 层高斯权重）
  bklv::shadow::setQuality(bklv::ShadowQuality::SMOOTH);   // 或 setQualityByName("smooth")
  BKLV_SHADOW_QUALITY=smooth ./dist/embed_imgui_gl    # 启动前用环境变量指定
  • 控件自己在 custom 层画的东西（滑块把手）不走外观层，直接调

bklv::shadow::drawSoft(...)

  • 真离屏高斯模糊没做：那要给三个后端各加一套离屏渲染 + 模糊 shader，

而 UI 阴影的羽化只有 10px 上下。档位开关留在这里，以后换实现不影响 JSON 与调用方

要记住的四条：

  1. 装饰走 JSON，语义留 C++：底/边框/文字/图片/状态动效由 layers 描述；换行截断、

图片缩放、进度弧这类走 custom 层，由控件自己画。

  1. 外观值在 applyTheme() 时取定，draw() 里不查主题（否则每帧几千次字符串查表）。
  2. 主题只覆盖没被显式设置过的值：label->setFontSize(18) 之后换肤不会改它；

要让它跟随主题就 label->setFontSizeExplicit(false)。

  1. 加控件外观要在 theme.json 的 widgets 数组里登记（不扫目录，romfs 限制）。

写成 @theme/color.x.y / @theme/metric.a.b 的引用在装载时解析： colors.json 的 key 拍平成 color.*，metrics.json 拍平成 metric.*。 皮肤缺的 key 回退 default。

不生成 imgui.ini

bklv 的绘制全部落在 viewport 的绘制列表上，不依赖 ImGui 窗口的位置和尺寸， 所以默认把 io.IniFilename 置空，ImGui 既不会读取也不会写出 imgui.ini。

// 默认就是关闭的，无需任何调用
bklv::App app;

// 想恢复 ImGui 默认行为（读写 imgui.ini）时：
app.setIniPersistenceEnabled(true);
// 或者用环境变量：BKLV_USE_INI=1 ./dist/embed_imgui_gl

实现位置：bklv::App::run() 里 ImGui::CreateContext() 之后、 第一次 NewFrame() 之前设置 ImGui::GetIO().IniFilename = nullptr。 这个赋值必须在那之前完成，之后改无效。

日志与调试窗口

日志用 BKLV_LOG_INFO(...) 等宏，输出带 文件:行号。日志同时进控制台与 Logger 的环形缓冲，界面上的调试日志视图（widgets/debug/debug_log_view.hpp 的 DebugLogView）读缓冲渲染； 它挂在宿主指定的调试层上（Shell 已移除，层级由宿主自己管），不吃输入。

已知的坑（都已处理）

  1. 字体必须惰性解析。 视图树是在 RunDemo 的参数里构建的，而字体在 App::run()

里才加载；如果 Label 在构造时绑定字体，会绑到 nullptr，文本永远测不出宽度。

  1. 字体加载后必须重排一次。 树构建时字体还没就绪，文本会测出 0 宽并被 Yoga 缓存。

App::frame 用 getFontGeneration() 检测字体变化并触发一次全树重算。

  1. invalidate() 不能用 YGUndefined 重算。 在 update() 里新建视图（虚拟列表

每帧都在建 cell）会触发 invalidate，如果传 YGUndefined，百分比宽高全部失去参照， 整棵树会塌成内容尺寸。现在用 App::getLayoutWidth/Height() 记住的画布尺寸重算。

  1. 滚动偏移不能重复叠加。 getLocalX/Y() 已含 translation，getX/Y() 只累加父节点，

否则滚动距离会被算两次（之前 500 的偏移变成了 1000）。

  1. 回收的 cell 可能正是当前焦点。 被回收时必须清掉"已自动滚动"标记，否则焦点转回来时不会滚动。
  2. 图片路径按进程工作目录解析，且加载失败会被 g_pathCache 永久缓存

（TEXTURE_CACHE_FAILED），只会打一条日志。所以要在项目根目录下运行； 出现"图片位置空着"时先确认工作目录，别急着怀疑渲染后端。

学习提示

  • Yoga：先配置父节点的 FlexDirection、JustifyContent、AlignItems、Gap 和

Padding；再设置子节点尺寸约束或 FlexGrow；调用 YGNodeCalculateLayout() 后读取 YGNodeLayoutGetLeft/Top/Width/Height()。Yoga 只算几何布局，不负责绘制。

  • Tweeny：用 tweeny::from(start).to(end).via(easing).during(frames).build() 创建动画；

每帧按经过时间调用 step(frames)，通过 peek() 读取插值。继续调用 to() 可添加关键帧， 用 on(tweeny::event::complete, callback) 监听完成事件。

  • Dear ImGui：负责接收输入、生成控件和绘制命令；窗口由平台层（SDL3 或 libnx）支持，

绘制由图形后端（OpenGL / GLES3 / Vulkan）完成。

  • 平台层：上层只跟 Platform 与 RenderBackend 两个接口打交道。

加平台写一个 Platform 子类，加图形 API 写一个 RenderBackend 子类，view 层不用动。

  • Switch 特有：构建带 -fno-rtti，类型判断用 View::asBox() 虚函数而不是 dynamic_cast；

主题与外观

两套主题，都在 resources/theme/<名字>/ 下：theme.json（显式 files[] 清单，不扫目录） + tokens/（colors / metrics）+ base|widget|view/ 外观。复制一套改名改 JSON 就是新皮肤； themes.json 的 available 列出可选主题，运行时 App::setTheme("glass") 切换。

主题定位关键做法
default纯扁平无阴影、无玻璃、无渐变；靠 1px 描边分面；color.common.shadow 全透明（代码驱动的软阴影也随之关闭）
glass玻璃质感只覆盖少量 tokens/（配色 / 圆角），外观与 files[] 留空 —— 缺的逐键回退 default；是"最小主题"的样板

外观 JSON 的四段

{
  "import": "base/box",          // 先继承一份，再逐字段合并（可变体可以用后缀拼名字）
  "box":   /* 尺寸/内边距/圆角/边框（影响布局）*/,
  "layers": [                    // 绘制结构，按顺序画
    { "op": "rect",  "id": "bg",   "fill": "@theme/color.surface.card", "radius": 10 },
    { "op": "text",  "id": "title", "color": "@theme/color.text.primary" },
    { "op": "glass", "id": "glass", "fill": "#1C1C1ECC" }
  ],
  "states": {
    "focused": {
      // self = 控件自身：视图级通道（translateX/Y、scaleX/Y、alpha、rotate、skewX/Y）
      "self": { "translateY": { "to": -4, "duration": 160, "easing": "cubicOut" } },
      // 层目标可以分组写；旧写法 "bg.fill" 仍兼容
      "bg":   { "fill": { "to": "@theme/color.highlight.background", "duration": 120 } }
    }
  },
  "transitions": { "enter": { ... } }
}

六种内置层：rect / text / image / shadow / glass / custom； 第三方可以注册自己的层（registerLayer<T>() 一行，参数模式声明一次，解析/缩放/设计器候选键自动跟上）。 层序：内置层按 JSON 书写顺序画（只有阴影、玻璃被提到最前）；声明 DECORATION / OVERLAY 的扩展层画在所有内置层之上。 高亮底必须排在内容层之前（hlBg 在 text/image 之前）；聚焦描边由浮层的焦点框绘制， 外观里不再需要 hlGlow/hlBorder 占位层。

主题数值的"计算"规则

  • 尺寸/字号按 1280×720 设计稿写，运行时 uiScale = 画布宽 / 1280；metric.* 取值时乘缩放（anim.* 毫秒、font.lineHeight 系数不缩放）。
  • 外观 JSON 里的 radius / strokeWidth / width / height / fontSize / inset / offset 会乘缩放；opacity（系数）与 duration（毫秒）不缩放。
  • 代码里写死的像素值不缩放 —— 想跟随比例就用主题 metric，或把数字写进外观 JSON。
  • 主题只覆盖"没显式设置过的值"：代码里 setCornerRadius(r, explicit=true) 之类的显式值优先于外观。
  • @theme/ 引用写错会硬失败（不静默回退成洋红）；主题 JSON 的 files[] 少写一项会以"主题里没有控件外观"静默回退。

JSON 视图与字段

JSON 描述视图树："type" 指定类型、其余键是属性、"children" 是子节点、"include" 引别的文件。 两段式：ViewTemplate（可缓存、与语言无关）→ instantiate()（解析 @i18n/ 等）。 结构错误返回 nullptr + 日志；未知属性只警告（带拼错提示）。上限：深度 32 / 节点 4096 / include 栈 32。

属性值的写法与求值时机

写法含义求值时机
12 / "12" / "12px"像素（按 720p 设计稿，运行时乘 uiScale）解析期
"50%"相对父容器的百分比（宽高与绝对定位四边）布局期
"auto"由内容决定（只有 width / height）布局期
@theme/color.a.b主题颜色实例化期
@style/metric.a.b主题数值实例化期
@i18n/key文案（resources/i18n/<locale>.json）实例化期
@res/x文件路径，相对 resources/使用处自己解析
"bind": "字段名"数据绑定：写到该类型的主属性（Label→text，Image→src）；别的类型要显式 "bindTo"列表项 setIndex 时

能写的 "type"（注册表实测）：Button。

一、通用取值语法

长度 / 数值

写法含义
12 或 "12"像素，按 1280x720 设计稿写，运行时乘 uiScale（见 core/ui_scale.*）
"auto"由内容决定（只有 width / height 支持）
"50%"相对父容器的百分比（width / height 与绝对定位的四边偏移支持）
"@theme/metric.a.b"引用主题数值。取值时已经乘过缩放，不要再自己乘

颜色

只支持两种写法（其它字符串直接报错）：

"#RRGGBB"        // 不透明
"#RRGGBBAA"      // 带 alpha，00 = 全透明
"@theme/color.a.b"

引用前缀（视图描述 JSON 的字符串属性）

前缀含义解析时机
@i18n/key文案，取 resources/i18n/<locale>.json 的 key实例化期（模板缓存里保留原文）
@theme/color.a.b主题颜色实例化期
@style/metric.a.b主题数值实例化期
@res/x文件路径，相对 resources/ 目录使用处自己解析
@icon/star内置图标字形（按名字，名字表见 media/icon_font.cpp）实例化期（TEXT 解析里换成 UTF-8 字形）
@icon/U+E000同上，按码位（名字表是子集，码位能取到字体里的全部字形）同上
长度/坐标/偏移都按 1280x720 写，和主题 metric、外观 JSON 用同一个基准： 解析时统一乘 uiScale（1080p 窗口里 100 -> 150），换分辨率不会错位。 不乘缩放的只有：百分比（"50%"）、auto、系数类（grow/shrink/alpha/图片 的 scale）、以及毫秒（动画时长）。写 @style/metric.x 时值已经乘过，不会重复乘。

引用前缀：@ 跨文件、& 同文件

前缀作用域例子
@别的文件（主题 / 文案 / 资源 / 内置图标）@theme/color.accent.base、@theme/metric.control.height、@i18n/xxx、@res/xxx、@icon/star
&同一份文件的 vars 块&color.accent、&number.row

$ 前缀只出现在键上，表示"这不是数据"（$comment 写注释、$files 是 i18n 的文件清单）； 出现在值位置上会被报错并提示改用 &。

  ]
}

五条规则（写错就报错，不静默降级）：

  1. 一个文件只有一个 vars，必须在顶层；嵌套出现 → 报错
  2. 只有 colors / numbers 两个子块；别的子块 → 报错
  3. 值可以是字面量（"#RRGGBB[AA]" / 12），也可以是 @theme/... 引用
  4. vars 之间可以用 $ 互相引用（链式，最多 4 层）；循环 → 报错
  5. & 的展开与"直接写那个值"完全等价 —— 缩放（uiScale）、opacity/duration 不缩放、

报错口径都由 resolveColor / resolveNumber 决定，vars 这一层不加工数值

vars 怎么和已有机制配合：

机制解决什么
@theme/...同一份跨文件的全局 token（主题）
vars + $同一份文件内的重复值（一眼看出这句话在说什么）
import整份外观的复用（父外观的字段被当前文件覆盖）

& 绑的是"写它的那份文件"：A import B 时，B 里的 $ 按 B 自己的 vars 展开，再合并。 想让 A 调 B 的值，直接在 A 里覆盖那个字段（import 的"当前文件优先"）。

明确不做：算式（"&number.gap * 2"、"100% - &number.x"）、结构复用（整组 inset / states / layers，那是 import 的活）、字符串/枚举变量、跨文件 &、子节点内的 vars。

缩放规则（记住这一条就不会算错）

会乘 uiScale不乘
metric.*（主题数值）、外观里的 radius / strokeWidth / width / height / fontSize / inset / offset / feather / spreadopacity（系数）、duration（毫秒）、metric.anim.*（毫秒）、metric.font.lineHeight（系数）

代码里写死的像素值不缩放。想跟随比例就写进主题 metric 或外观 JSON。

三、控件外观 JSON

文件放在 resources/theme/<主题>/base/（基础控件：单个容器/元素）或 base/widget/ （二级控件：引用 base 组合出来的），必须在该主题 theme.json 的 files[] 里登记 （不扫目录，没登记 = 不生效 + 一条 warn）。

外观名 = 相对主题根的路径去掉扩展名：base/button.json → "base/button"； 变体是后缀：base/button.json + 变体 primary → 文件 base/button.primary.json。

一份外观 = 三段，layers 必填（纯布局控件写 "layers": []），另有一个可选的 import：

{
  "import":  "base/box.component",
  "box":     { "…": "盒模型与布局" },
  "layers":  [ { "op": "rect", "…": "绘制结构，按数组顺序画" } ],
  "states":  { "focused": { "bg.fill": { "to": "#ffffff", "duration": 120 } } }
}

import：外观引用外观

  • 值可以是字符串或字符串数组；逐字段合并，当前文件优先。
  • 对象（box / states / 单个 state）递归合并；layers 按 id 合并

（同 id 的层合并字段、子赢；新 id 追加在后面）；其它数组整体替换；标量覆盖。

  • 循环引用 / 链深 > 8 / 父级不存在 → 编译失败（错误信息指出是哪个 import）。
  • 一行里放多个内容层时：层不是流式布局（用 inset 排队），并给 box 写

"measureContent": "sum" 让固有宽度按行求和（默认取"最宽的那一层"）。

层序有三条硬约定（theme_test 会遍历两套主题的每一份外观断言）：

  1. glass 层必须排在自己的内容层之前：玻璃画在这一层的位置上，后面的内容层压在它上面；

排反了内容会被玻璃盖住。详见 glass-layer.md。

  1. hlBg（焦点高亮底）必须在 text / image / custom 之前 —— 排反了聚焦时那块

不透明高亮底会把内容盖住（开关/单选图形消失过）。

  1. shadow 层必须在本控件的底色之前。
  2. hlGlow / hlBorder 排在最后（画在内容之上）。

custom 层的内容留给 C++（AppearanceView::drawCustomLayer）：进度弧、滑块轨道、 开关图形这类语义绘制不该塞进 JSON，否则等于写解释器。

层 import：{ "import": "base/layer/xxx" }

layers 数组里可以放一条只有 import 的条目（没有 op），它会就地展开成那个外观的 layers 数组（它的 box / states / children 不会带进来），后面的层照常排在它之后：

"layers": [
  { "import": "base/button/frame" },      // 展开成 shadow / bg / hlBg
  { "op": "text", "id": "title", "data_id": "text" }
]
  • 适合把「阴影」「玻璃」「背景框」这类基础层拆成独立文件反复叠加；
  • 可以写数组一次导入多份：{ "import": ["base/layer/shadow", "base/layer/border"] }；
  • 被导入文件自己的顶层 import 也会先解析（例如 base/button/frame 本身）；
  • 循环引用、深度 > 8、文件不存在、没有 layers 都会报错；
  • 层 id 不能重复（导入层与本地层撞名会报错）—— states 与字体覆盖都按 id 找层。
  • 同一个 bundle 的 import 指令会合并：顶层 import 的父级写了 { "import": "base/layer/shadow" }，

子级再写 { "import": "base/layer/shadow", "cutout": true } 时合成一条（子级参数覆盖父级）， 不会展开两次变成重复 id。所以“继承基外观的 states + 覆盖某个 bundle 的参数”可以直接写。

  • 单层 bundle 可以就地覆盖：import 旁边的字段会合并到那一层，例如

{ "import": "base/layer/shadow", "cutout": false, "offset": [0, 8] }； 也可以改 id 在同一外观里叠两层阴影。多层 bundle 带覆盖字段会报错（语义不明确）。

key 是 "<层 id>.<属性名>"，值是一个补间目标：

"states": {
  "focused": {
    "hlBg.fill":         { "to": "@theme/color.highlight.background", "duration": 120, "easing": "quadraticOut" },
    "hlGlow.strokeWidth": { "to": 11, "duration": 120 }

}
字段说明
to必需。颜色或数值；数值按长度语法（会乘缩放），颜色与 opacity 不乘
duration毫秒，省略 = 0（瞬时）
easing省略 = linear

可用属性名：fill stroke color/textColor strokeWidth radius opacity offsetX offsetY insetTop insetRight insetBottom insetLeft fontSize feather spread。

可用 easing：linear、quadraticIn/Out/InOut、cubicIn/Out/InOut、quarticOut、 quinticOut、sinusoidalIn/Out/InOut、exponentialOut、circularOut、backOut、 backInOut、bounceOut、elasticOut、stepped。

分组目标与 self（视图级通道）

除了上面的扁平写法，每个状态还可以按目标分组；self 表示控件自身， 走视图级通道（整棵子树一起动的绘制期变换）：

"states": {
  "focused": {
    "self": { "translateX": { "to": 100, "duration": 160, "easing": "cubicOut" } },
    "bg":   { "fill": { "to": "@theme/color.surface.hover", "duration": 120 },
              "radius": { "to": 10, "duration": 120 } }
  }
}
  • self 的可用通道：translateX / translateY / scaleX / scaleY / alpha /

rotate / skewX / skewY（位移乘缩放，其余是系数/弧度不缩放）；

  • 层目标里的属性名与扁平写法完全一致；
  • 旧的 "bg.fill": {...} 继续支持（静默兼容，不告警）；
  • 多个状态同时激活时后激活的赢；状态关闭时平滑回默认值（120ms）；
  • 视图通道是绘制期变换：不重排、不占位，命中区域不跟随移动。

状态名不限于内置的 focused / pressed / disabled；控件自定义的（如 Cell 的 selected） 由控件自己触发。重算目标时会先撤同一通道正在跑的补间。

变体与回退

  • 变体：setAppearanceVariant("sidebar") → 读 <控件名>.sidebar.json

（tab_cell.sidebar.json、rectangle.card.json、button.primary.json 都是这么来的）。 同一控件要多套尺寸就加变体文件，别在代码里改高度。

  • 回退链：当前主题 → default 主题 → 找不到文件时给空外观 + 一条 warn（不崩）。
  • 编译失败：op 不认识、states 引用了不存在的层、@theme/ key 不存在、

缺 layers → 打 error 日志并返回空外观。不会静默回退成洋红/0。

外观契约：requires

代码需要的内容槽/几何层，可以在外观 JSON 里显式声明（只能加严，不能替代代码契约）：

{
  "layers": [
    { "op": "text", "id": "text", "data_id": "text" }
  ],
  "requires": {
    "content": ["text"],
    "layers": ["bg"]
  }
}
  • requires.content：必须存在 op=text 且 data_id 等于该名字的层；
  • requires.layers：必须存在同 id 的层（不校验 op）；
  • 校验发生在 import 合并与编译之后；失败会写 error 日志，

validateThemeAppearances() 返回失败；

  • 代码侧还注册了内置契约（如 base/widget/button.text 必须有 text 槽、

base/slider/slider 必须有 track/fill/knob/geometry、 base/hint_item 需要 icon/label、base/header_icon 需要 icon、 base/dropdown_item 与 base/text_field 需要 text）。 内容槽既可以是 op=text，也可以是 op=image（图标槽）。JSON 的 requires 与内置契约取并集，不能放宽；

  • glass 变体自动继承基名契约（button.text.glass → button.text）。

<主题>/sound.json：全局 UI 音效

主题根下的独立文件（不写进 files[]，它不是控件外观）。缺了回退 default 主题。

{
  "triggers": {
    "click":      "@res/audio/click.wav",
    "focus":      "@res/audio/focus.wav",
    "focusError": "@res/audio/focus_error.wav",
    "back":       "@res/audio/back.wav",
    "clickError": "@res/audio/click_error.wav"

}
  • 音效跟随主题目录：sound.json 从当前主题目录读取（ThemeData::getDirectory()），

  • 路径三种写法：
  • @res/audio/x.wav：相对 resources/（全局素材）；
  • @theme/audio/x.wav：相对当前主题目录（主题自带素材）；
  • 相对路径（audio/x.wav）：同样相对当前主题目录；绝对路径原样使用。
  • 支持单声道/立体声 PCM WAV（8/16/24/32-bit、float32），运行期重采样到 48kHz 并缓存；
  • 触发点大小写/下划线不敏感；不认识的触发点只警告；
  • 文件缺失、解码失败 → 回退到代码合成音（现有 Sound），不影响 UI；

// base/widget/button.text.json
"states": {

视图过渡（transitions）

外观 JSON 的顶层 transitions 段描述视图生命周期的动画：enter / exit / show / hide。 和 states 的分工：states 管控件内部状态（选中/聚焦/按下…），transitions 管出现与消失。

"transitions": {
  "enter": {
    "duration": 200, "easing": "quadraticOut",
    "translateX": { "from": -60, "to": 0 },
    "alpha":      { "from": 0,   "to": 1 },
    "layers": {
      "title": { "when": "after", "duration": 140,
                 "offsetX": { "from": -20, "to": 0 },
                 "opacity": { "from": 0,   "to": 1 } }
    }
  },
  "exit": { "alpha": { "from": 1, "to": 0 } },
  "show": { "alpha": { "from": 0, "to": 1 } },
  "hide": { "duration": 0, "alpha": { "from": 1, "to": 0 } }
}
位置可写的键
事件级duration（毫秒，默认取主题 metric.anim.normal）、easing、delay
视图级通道（整树一起动）translateX / translateY / scaleX / scaleY / alpha
层内通道layers.<层id>.<属性名>，属性就是 states 那 16 个
通道对象from（可省）、to（必写）、duration、easing、delay
层内条目级when（with 默认 / after）、delay、duration、easing

四条语义：

  1. 不做预设 —— 没有 "type": "slideFade" 这种枚举，效果直接写通道名（写了 type 会报错并列出可选通道）
  2. 外观里没写 transitions → 调用方用默认的淡入淡出；事件里没写某个层 → 那层不动，跟着整树一起淡
  3. when: "after" = 这条层内动画延后到视图级动画结束才开始（解析期就把它加进 delay）；

出场 / 隐藏写 after 只会得到一条警告并按 with 处理 —— 那时视图已经看不见了

  1. duration: 0 = 瞬变；写 when: "before" 会报错（出现之前 / 消失之后看不见，

想让内容先动、整页后动请用 delay 表达提前量）

运行时（core/transition_player.* + anim/transition.hpp 的 ViewTransition）：

  • 外观里写了就用外观的：视图级通道走 View 的绘制期变换（整树一起动、过渡期间零重排），

层内通道写进 AppearanceInstance（开始前先撤掉同通道的状态补间 —— 状态动效和过渡不能同时对一条属性下手）

  • 没写就是默认淡入淡出（入场/显示 0→1、出场/隐藏 1→0），时长取主题 metric.anim.normal
  • 没写 from 的通道起点取当前值
  • ViewTransition::getActiveDuration() 报本次实际时长（spec 的 totalMs 或配置值），

Shell/Pager::getTransitionDuration() 报的就是它 —— 出场播完才摘页/摘弹层靠这里

  • playShow / playHide 只有"外观里写了"或"默认淡入淡出"两种；隐藏要不要真的 GONE/摘掉

由调用方在回调里做（提前设 GONE 动画根本播不出来）

  • spec 路径收尾不复位（终值就是外观里写的，比如出场停在屏幕外）；预设路径照旧复位

时间账（解析期算好）：totalMs = max(事件时长, 每条条目 delay + duration)， 调用方拿 totalMs 决定"这段动画播完了"的时机 —— 出场播完才摘页 / 摘弹层，报早了动画会被砍。

扩展图层类型（第三方）

内置 op 只有 6 种：rect / text / image / shadow / glass / custom。 别人可以加自己的，而且不需要改 bklv/ 里任何文件：写一个文件 + 注册一行， 主题里就能写 "op": "你的名字"。完整可运行的样例就在本节（stripe 与 quad 两份）。

推荐写法：注册模板 + 参数模式

#include "bklv/layer/layer_register.hpp" // registerLayer<T>() 模板

struct StripeLayer
{
    static constexpr const char* kName     = "stripe";   // JSON 里的 op 值
    static constexpr const char* kLabel    = "斜条纹";    // 设计器显示名
    static constexpr const char* kIdPrefix = "stripe";   // 可省，默认用 kName
    static constexpr const char* kHelp     = "斜条纹：angle / lineWidth / gap";
    static constexpr auto kOrder = bklv::compile::LayerOrder::DECORATION;

    // 参数模式：声明一次，引擎负责解析（类型 / 720p 缩放 / 拼错提示），
    // 设计器的候选键、中文名与 ENUM 下拉都由它派生 —— 不用手写 keys，也不用写 parse。
    static std::vector<bklv::compile::LayerParam> params()
    {
        return {
            bklv::compile::LayerParam::number("angle", 45.0f, "角度"),
            bklv::compile::LayerParam::pixels("lineWidth", 2.0f, "线宽"),
            bklv::compile::LayerParam::pixels("gap", 16.0f, "间距"),
        };
    }

    static void draw(const bklv::compile::LayerDrawContext& ctx);
};

// 在你自己的初始化里调一次（第三方程序就是在 main 里调）
bklv::compile::registerLayer<StripeLayer>();

参数类型（五种）

工厂JSON 写法说明
LayerParam::number(name, def, label)0.5数字，不缩放（系数 / 角度 / 比例）
LayerParam::pixels(name, def, label)16 / "@style/metric.x"像素量，按 720p 乘 uiScale
LayerParam::color(name, def, label)"#RRGGBB" / "@theme/color.a.b"颜色
LayerParam::boolean(name, def, label)true / false布尔
LayerParam::enumeration(name, values, defIndex, label)"vertical"候选取值；拼错只警告并保持默认

JSON 里没写 = 用模式里的默认值（不是 0）—— "没写"和"写 0"是两件事。 参数值按声明顺序存在 AppearanceLayer::params（每层上限 8 个，超了注册期报错）， 绘制钩子按名字取：

static void draw(const bklv::compile::LayerDrawContext& ctx)
{
    const float angle = bklv::compile::numberParam(ctx, "angle", 45.0f);
    const float gap   = bklv::compile::numberParam(ctx, "gap", 16.0f);
    const bool  mono  = bklv::compile::boolParam(ctx, "mono", false);
    const char* mode  = bklv::compile::enumParam(ctx, "mode");  // 枚举值翻回字符串

    ImDrawList* drawList = static_cast<ImDrawList*>(ctx.drawList); // 不透明指针，见下
    // ctx.rect 已含这一层的矩形、圆角与有效 alpha；
    // ctx.layer.fill / .radius / .inset … 是引擎白送的通用字段（见下）
}

**void* 是有意的**：layer/ 不认识 ImGui 与 widgets，所以上下文里的 drawList（= ImDrawList*）与 view（= AppearanceView*）用不透明指针传， 扩展层自己转回去。

引擎白送的字段（任何 op 都能用）

fill / stroke / color(textColor) / strokeWidth / radius / opacity / fontSize / width / height / feather / spread / cutout / inner / inset / offset / gradient， 外加元信息 op / id / data_id / align / valign / scaling —— 全都解析好放在 ctx.layer 上，绘制钩子直接读。完整清单见 compile::engineLayerKeys()。

别把这些名字再声明成参数：那样同一层会有两份值（引擎一份、参数槽一份）。注册时会警告。

需要自己的结构参数时（可选 parse 钩子）

三条硬规则

  1. 参数名不许占用引擎保留键：op / id / width / height / inset / align / valign /

  1. 失败要报错，不要静默降级：参数类型不符、ENUM 没给候选、参数超过 8 个、参数名重复，

都在注册期或解析期报清楚（解析失败 = 整份外观编译失败并记日志）。

  1. draw 里不要再查 JSON、不要再查主题：外观值在编译期就定下来，绘制只读

ctx.layer / ctx.rect / ctx.type（和内置层同一条约定）。

三档节点（互斥，写两个报错）

写法建出什么
"appearance": "<外观名>"一个 AppearanceView（名字规则与 AppearanceView 一样，含 .变体）
只写 "box"一个纯布局 Box（递归嵌套的载体，想套多深都行）
"ref": "<视图模板名>"用主题 view/ 里的视图模板实例化 —— 库里已有的一切控件都能这么引用

公共可选键：

  • "box"：覆盖/追加盒模型字段（只覆盖写了的字段，沿用"没写不动"的既有约定）
  • "children"：递归（ref 节点不能再写，它的子节点写在模板里）
  • 内容槽："text" / "icon" / "info" —— 实例化后套到 AppearanceView 的既有槽位上。

icon 支持 "@icon/star" 这种名字（会查字形），也可以直接写字形

与 layers 的本质区别

  • layers 不进布局：只是在这块矩形里画一笔笔（靠 inset/align 手排）
  • children 进布局：是真正的子视图，参与 flex 排版、能聚焦、能滚动

所以：要"画装饰"用 layers，要"装控件"用 children。

错误规则（全部硬错误，不静默降级）

  • appearance 与 ref 同时写 -> 报错
  • 三样都没写 -> 报错（不知道该建什么）
  • ref 节点再写 children -> 报错（子节点写在模板里）
  • 嵌套深度上限 16，超过报错
  • 循环引用：A 的子节点里又引用 A（或 A→B→A）-> 报错并停止构建
  • box 段里不认识的键：按主 box 段的既有行为处理（children 要与 box 平级，

写进 box 里不会生效 —— 这一点有测试钉住）

有什么、没什么（当前版本）

有：

  • 三档节点、任意递归、box 覆盖、内容槽、循环与深度保护
  • 子节点自己的外观由它自己负责（states / transitions 照常用）

没有（有意留到后面，不是忘了）：

  • 父外观改子节点的状态：states 的寻址空间仍然只有"层"（<层id>.<属性>），

不会扩成树路径

  • ~~children 的 box 段只认少数几个键~~ 已解决：它现在与外观主 box 段共用同一份解析

（theme/appearance_box.cpp），所以 axis / alignItems / justifyContent / margin / padding / minWidth / 背景 / 圆角 / 边框 / measureContent 等全套字段都支持， "只覆盖写了的字段"（hasXxx 标记）的语义也天然一致

运行期能力

帧预算：界面永不卡，任务可以晚

App::setFrameBudgetMs(4)（默认 4ms）给"可延后工作"一个每帧时间预算： 后台回调与 delay 到期任务、纹理上传、动图换帧、SVG 栅格化、纹理缓存淘汰 —— 用完就停手、下一帧继续， 且不丢活（没跑的回调放回队首、到期延迟放回表里）。布局 / update 业务 / 输入 / 绘制不吃预算。

图片：异步解码 + 背压

  • Image::setImageFromFileAsync(path)：后台解码（线程池）→ 回主线程上传；setDecodePriority() 越小越先。
  • pumpDecodeQueue() 按 getDecodeConcurrency()（默认 4）限制在飞解码数；pumpUploads() 按 getMaxUploadsPerFrame()（默认 2）+ 帧预算消费上传。
  • 滚出视口/换图：cancelDecode(key) 直接丢弃，不占上传配额；同一路径不重复解码。
  • 纹理预算：setTextureBudget(n) + trimTextureCache()（超预算淘汰 refCount==0 的 LRU，每帧增量收）。
  • 帧内同步加载是违规：setImageFromFile() 在帧内被调用会打一条节流警告。

约定与已知坑

  • 零警告：-Wall -Wextra -Wpedantic，构建出现一个 warning 就算失败（CI 也这么判）。
  • update() 路径不许读 ImGui::GetIO()：无窗口时没有上下文会空指针；时间用 core/time.hpp。
  • 布局是延迟的：invalidate() 只标脏，真正重算在下一帧；不要"改完立刻读尺寸"。 静态页面布局次数应为 0，排查用 BKLV_FORCE_RELAYOUT=1。
  • 回收列表 cell 必须重写 setSectionIndex：分段路径走它，只重写 setIndex 会让绑定函数永不触发（列表整条空白）。
  • 显式值优先：setCornerRadius(r, explicit=true) 之类不会被外观 JSON 覆盖；外观套用一律 explicit=false。
  • 高亮底顺序：hlBg 必须在内容层之前，否则聚焦时整块不透明底把内容盖住（开关/单选曾整片消失）。
  • 玻璃层顺序：阴影(0) → 玻璃(1) → 其余(2)；玻璃不能排到第一个，否则半透明阴影把它压暗。
  • 顶栏/底栏只是一块区域：任何主题都不给它画底色或边框（排反了会多出一道横线）。
  • 输入 → 响应同帧生效：App::frame 的次序是"布局 → 输入 → 绘制"，别把输入挪到绘制之后。
  • 帧内同步加载图片是违规：批量/滚动场景用 setImageFromFileAsync。
  • JSON 里没有通用回调：只能写"名字"（data / itemBinder / onEnd / bind）， 行为必须在 C++ 注册（结构归 JSON、数据与行为归 C++）。Box 也不能在 JSON 里设可聚焦。
