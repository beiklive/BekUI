bklv 架构

跨平台 C++17 界面库 · 一个 View 就是一个 YGNode

布局交给 Yoga（Flexbox）算，绘制交给 Dear ImGui 的 ImDrawList。 控件层不接触任何图形 API，所以换渲染后端（OpenGL / Vulkan / OpenGL ES 3）不用改业务代码； 换平台（SDL3 / libnx）只加一个 Platform 子类。

四条不能破的约定

① 没有独立渲染树。一个 View 持有一个 YGNode， 通过 YGNodeSetContext 互相指回去。布局是 Yoga 递归算的，绘制是 View::draw() 递归画的， 两者顺序天然一致。
② 控件层不出现图形 API。只接收 ImDrawList* 与 ImTextureID。 判断标准就是一句 grep：views/ 里不许出现 gl* / vk*。
③ 平台与图形后端都是编译期确定的。不运行时探测、不搞注册表。 选择点在各平台自己的 createBackend() 里，几行 #if 而已。
④ 资源与字体按平台解析。桌面资源在可执行文件旁、Switch 在 romfs； 中文桌面读系统字体、Switch 用 pl 服务取内置共享字体并串 fallback 链。 代码里统一写相对路径。

帧循环（App::frame）

  1. 字体变化检查 — 视图树常在 App::run() 之前建好，字体就位后要触发一次全树重排
  2. 布局 — 每帧按当前画布尺寸跑一次 YGNodeCalculateLayout
  3. 动画与逐帧逻辑 — Ticking + 各 View 的 update()（滚动惯性等）
  4. 输入与焦点 — hitTest、方向导航、动作触发（读的是上一帧的命中结果）
  5. 业务回调 — onUpdate
  6. 绘制视图树 — 画在 viewport 绘制列表上，不创建 ImGui 窗口
  7. 提示栏 + ImGui 窗口 — onDrawWindows（日志窗口等），最后才 ImGui::Render()

模块清单

core/ — 14 个模块

模块职责
view.*视图基类：Yoga 样式透传、布局失效、绘制模板、测量回调、焦点与动作

platform.*平台接口：窗口、事件循环、系统能力（电池/网络/亮度/语言/剪贴板）

gamepad.*手柄输入抽象（桌面 SDL3 / Switch libnx）
theme.*Style 数值表与颜色主题
font.*字体加载：各平台取字体的方式不同（见约定④）
resource.*资源路径解析（见约定④）
image_decoder.*图片解码：macOS 走系统 ImageIO，其余走 stb_image
logger.*四级日志 + 时间戳 + 文件行号 + 环形缓冲（界面日志窗口读它）
time.*Animatable 补间、Ticking 注册表、缓动函数（自带实现，不依赖 tweeny）

已经踩过、写进约定的坑

坑现在怎么做
OBJECT 库的目标文件不会透过 INTERFACE 库传递bklv::bklv 接口里显式写 $<TARGET_OBJECTS:>
ScrollingFrame 不拥有内容视图换内容必须用 evictContentView()，不能直接覆盖
RecyclerCell 默认绝对定位当普通控件用时构造参数传 false（否则全叠在原点）
鼠标点击只聚焦不执行想点一下就执行，控件里设 onPointerAction = true
Switch 的 elf2nro --romfsdir 被静默忽略改成两步：build_romfs 再 --romfs=
ImGui 内存字体默认接管所有权共享内存必须设 FontDataOwnedByAtlas = false
后端未就绪被当成解码失败并永久缓存未就绪不缓存，由 Image::update() 补加载
